# AutoProdScripts

Windows-приложение (WPF, .NET 8) для ежедневной работы с репозиторием продакшн-SQL-скриптов: ветка → SQL → commit/push → Create PR в Azure DevOps.

Интерфейс: **только русский**.

Репозиторий: https://github.com/SergeyKV00/AutoProdScripts

## Требования

- Windows 10/11
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) (для сборки)
- [Git for Windows](https://git-scm.com/download/win) в `PATH`
- PAT Azure DevOps с правами на Code (Read & Write) / Pull Requests

## Сборка и запуск (разработка)

```powershell
git clone https://github.com/SergeyKV00/AutoProdScripts.git
cd AutoProdScripts
dotnet restore AutoProdScripts.sln
dotnet build AutoProdScripts.sln -c Debug
dotnet run --project src\AutoProdScripts\AutoProdScripts.csproj
```

Либо откройте `AutoProdScripts.sln` в Visual Studio 2022.

## Portable-публикация (копируемая папка)

Self-contained папка `win-x64` (не MSI, не обязательный single-file):

```powershell
dotnet publish src\AutoProdScripts\AutoProdScripts.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -o .\publish\AutoProdScripts
```

Или скрипт:

```powershell
.\packaging\publish.ps1
```

Скопируйте папку `publish\AutoProdScripts` на любой ПК и запустите `AutoProdScripts.exe`.

## Первый запуск

1. Укажите путь к репозиторию (например `C:\Users\...\ProductionScripts`).
2. Заполните Azure DevOps: Org/URL (`https://cit-damu.visualstudio.com/`), Project, Repo, PAT.
3. Выберите базовую ветку из списка (обычно `master`) — выбор сохраняется.
4. **Сохранить и открыть**.

Настройки: `%AppData%\AutoProdScripts\settings.json`  
PAT: Windows Credential Manager и/или DPAPI-файл в той же папке.

**Быстрое добавление.** Кнопка на панели «Файлы» открывает диалог: несколько SQL-скриптов, папка по первому `USE` из файла `mapping/use-folders.yaml` рядом с программой (папка копируется в сборку; не секрет, только имя БД и относительный путь). Справа — дерево назначения; папку можно выбрать вручную. «Сохранить» только записывает файлы, «Создать PR» после записи вызывает обычный Create PR. Меню «Файл → Проанализировать папки и USE» читает только папку `2026` репозитория скриптов, показывает, где в одной папке смешаны разные `USE`, и может дописать в mapping приложения только однозначные пары.

## Раздел «Запросы»

Переключатель «Репозиторий / Запросы» на панели. Раздел не связан с git и PR: это выполнение SQL на настроенных подключениях к MS SQL Server.

**Подключения:** «Настройки → Подключения к базам» или кнопка «Подключения…». Строку подключения (или целый блок `<connectionStrings>`, или пары из `appsettings.json`) можно вставить — поля заполнятся сами. Список лежит в `%AppData%\AutoProdScripts\connections.json`, пароли — только в Windows Credential Manager. У каждого подключения есть метка среды; новое по умолчанию «БОЙ». Регионы — в `%AppData%\AutoProdScripts\regions.json`.

**Кластер или база.** Подключение ведёт либо к конкретной базе, либо к кластеру (без базы, например строка без `Initial Catalog`). Это выбирается в поле «Куда подключаться» и видно в списке и рядом с кнопкой запуска. На кластере скрипт должен сам назвать базу (`USE ИмяБазы` или `База.dbo.Таблица`), иначе приложение предупредит: запрос ушёл бы в базу по умолчанию.

**Только чтение.** Скрипт разбирается парсером `ScriptDom`; разрешено лишь явно перечисленное: `SELECT`, переменные, `IF`/`WHILE`/`TRY`, `USE`, создание и изменение временных таблиц `#…` и табличных переменных. `EXEC`, управление транзакциями, изменение обычных таблиц, `OPENQUERY`/`OPENROWSET`, блокирующие подсказки и всё незнакомое отклоняется. Скрипт выполняется в транзакции, которая всегда откатывается. Это защита приложения, а не сервера: надёжнее всего логин с правами только на чтение.

**Запуск:** F5 (выделенный фрагмент выполняется отдельно). Переменные без `DECLARE` становятся параметрами; для сравнения с колонками `varchar` выбирайте тип VARCHAR, иначе сервер может не использовать индекс. Есть лимит строк (после него выполнение останавливается), отмена, копирование и экспорт в CSV.

Ограничения: `#таблица`, созданная в пакете с параметрами, не видна после `GO`; чтение через linked server внутри транзакции может потребовать MSDTC.

**Параметры.** `WHERE Id = @id` без `DECLARE` — справа появится поле `@id`. Значение вводится без кавычек.

**Explorer** (слева). Сверху — кнопки: новое подключение, обновить дерево, свернуть всё, настройки отображения (скрывать системные объекты, какие типы объектов показывать). Ниже — сворачиваемая секция «Открытые редакторы» и переключатель «Подключения / Библиотека» (по умолчанию — «Подключения»).

В «Подключениях» — дерево: группы → подключения (состояние рядом с именем: ○ отключено, ◌ подключение, ● подключено, ↻ переподключение, ✖ ошибка) → «Базы данных» → база → таблицы, представления, процедуры, функции, синонимы, последовательности, триггеры, схемы, «Безопасность» (пользователи, роли); у таблицы — столбцы, ключи, индексы, ограничения, триггеры. Всё грузится при раскрытии узла. Меню подключения: подключиться/отключиться/переподключиться, проверить, новый SQL-редактор, обновить, настройки, «на основе текущего», переименовать, переместить в группу, удалить (удаляются только настройки и пароль, не база). Меню таблицы: просмотр данных (TOP 1000), структура, DDL, генерация SELECT/INSERT/UPDATE/DELETE (только текст — выполнить изменяющий SQL раздел не даст), копировать полное имя, обновить, экспорт в CSV; пункты без прав (SELECT, VIEW DEFINITION) выключаются. Объект можно перетащить в редактор — вставится полное имя; F12 в редакторе (или «Показать в Explorer») находит объект под курсором в дереве. Поиск фильтрует подключения и уже загруженные объекты. Раскрытые узлы, фильтры, вид и подключённые подключения восстанавливаются после перезапуска (`explorer.json`).

Среды (БОЙ/ТЕСТ/РАЗРАБОТКА) заменены группами: при первом запуске старые подключения попадают в группы PROD/TEST/DEV. Если подключение — к кластеру (без базы), рядом с ним во вкладке появляется выбор базы; база запоминается только для этой вкладки.

**Открытые скрипты и вкладки.** Слева — Explorer: сверху «Открытые» (все вкладки), ниже «Библиотека». Над редактором — вкладки; «＋» (Ctrl+N) создаёт новый скрипт, Ctrl+O открывает файл .sql в новой вкладке, Ctrl+W закрывает вкладку, Ctrl+Tab переключает. Точка «●» — несохранённые изменения. Открытая вкладка и скрипт библиотеки — разные вещи: вкладка может быть черновиком (курсивом, «не в библиотеке») или ссылаться на скрипт; в библиотеку текст попадает только по «Сохранить». У каждой вкладки своё подключение (или «По регионам»), свои параметры, результаты и запуск — разные вкладки можно выполнять одновременно. Открытые вкладки с несохранённым текстом и подключениями восстанавливаются после перезапуска (`open-tabs.json` рядом с настройками; значения параметров и результаты не сохраняются). Цепочка открывается одной вкладкой.

**Библиотека** (панель слева). «Сохранить» (Ctrl+S) записывает скрипт: название, группа (вложенность через `/`), теги, описание, подключение, подписи, типы и значения по умолчанию параметров. Щелчок (или Enter) открывает скрипт. Поиск идёт по названию, описанию, группе, тегам, подключению, базе и тексту SQL; есть фильтры по подключению и тегу, избранное и недавно запущенные (правая кнопка мыши — меню скрипта). Ctrl+S сохраняет текст и типы параметров; подключение скрипта меняется только в «Свойствах», чтобы временный запуск на другом сервере не запоминался.

Файлы: `%AppData%\AutoProdScripts\library\scripts\*.json` (по файлу на скрипт), избранное и даты запуска — `library\state.json`. Введённые при запуске значения не сохраняются; значение по умолчанию сохраняется только если задано в «Свойствах».

**Цепочки** («＋ Цепочка» в библиотеке) выполняют сохранённые скрипты по очереди, каждый на своём подключении. Пример «сотрудник не синхронизируется из СУР в МД»:

1. Создайте цепочку и добавьте два шага. SQL пишется прямо в редакторе справа (или выбирается скрипт из библиотеки).
2. Назовите параметры одинаково (`@MoId`, `@Iin`) и выберите каждому шагу подключение. Одноимённые параметры станут общими и вводятся один раз.
3. У первого шага оставьте «не выполнять следующие шаги, если строк нет» и текст «Сотрудника нет в СУР», у второго — «Сотрудника нет в МД».

Где хранится скрипт шага:
- **в цепочке** (по умолчанию) — «Сохранить в библиотеку…» вынесет его в отдельный скрипт, а шаг будет ссылаться на него;
- **в библиотеке** — правки в редакторе шага не записываются сразу: «Обновить в библиотеке» меняет скрипт везде, «Сделать копию в цепочке» оставляет изменения только здесь. При сохранении цепочки приложение спросит об этом само. Запускается всегда то, что на экране.

Передача данных между шагами:
- **значение** — у параметра выберите «Колонка шага N» и укажите имя колонки. Если шаг вернул несколько строк с разными значениями, приложение покажет их и спросит строку один раз: из неё берутся все параметры всех следующих шагов;
- **набор строк** — задайте шагу имя таблицы (например `#people`), следующие скрипты читают из неё: `SELECT … FROM #people`.

Берётся первый набор результатов шага. Результат, обрезанный по лимиту строк, дальше не передаётся. Ошибка останавливает цепочку; все проверки (скрипты, подключения, значения) выполняются до первого запроса. Колонки типов `sql_variant`, `geography`, `hierarchyid` передавать нельзя. Файлы цепочек — `library\chains\*.json`; удаление скрипта библиотеки, на который ссылается шаг, не даст запустить цепочку.

**Обмен файлами.** «Экспорт всего…» в библиотеке или правая кнопка по записи или группе → «Экспортировать…». Получается файл `*.apsq`; цепочка берёт с собой скрипты, на которые ссылается. Паролей, адресов серверов, значений параметров (и по умолчанию тоже), избранного в файле нет. **Текст SQL и описания выгружаются как есть** — 12-значные числа, похожие на ИИН, приложение подсветит перед сохранением, но проверить нужно самому.

«Импорт…»: сопоставьте имена подключений из файла со своими и для каждой записи выберите: добавить, сделать копию, обновить своё или пропустить. Если запись отличается от вашей, по умолчанию создаётся копия — своё молча не перезаписывается; значения по умолчанию при обновлении остаются вашими. Экспорт всей библиотеки годится и как резервная копия.

**Регионы.** Для одинаковых таблиц в базах вида `KMIS_ast`, `KMIS_vko` на разных кластерах.

1. Заведите по одному подключению к каждому **кластеру** (без базы).
2. «Подключения…» → вкладка «Регионы», регионы сгруппированы по кластерам: код, название (необязательно), кластер. Можно вставить списком — строка `2 кластер:` и под ней коды, либо `ast; Астана; Кластер A`. Все базы одного региона считаются лежащими на одном кластере.
3. Скрипт: в списке подключений выберите «🌍 По регионам», задайте базу и отметьте регионы. Достаточно `KMIS` — код добавится в конец (`KMIS_ast`); если код нужен в другом месте, укажите `{region}`, например `{region}_KMIS`. SQL пишется без `USE` и имени базы. Шаблон сохраняется со скриптом («Сохранить как…» или «Свойства»), отмеченные регионы — нет.

Результаты объединяются в одну таблицу ровно с колонками скрипта (если у какого-то региона колонки другие — отдельной таблицей). Регион строки — служебные данные: в таблицу, копирование и CSV он не попадает, но галочка «Группировать по регионам» показывает строки группами с названием региона. Нужен регион в самой выгрузке — добавьте колонку в SQL, например `SELECT DB_NAME() AS Base, …`. Одновременно не больше двух запросов на кластер и восьми всего. Ошибка в регионе не останавливает остальные: итог помечается «ДАННЫЕ НЕПОЛНЫЕ», строки такого региона в таблицу не попадают. Лимит строк действует на каждый регион. Недоступная база может отвечать около 10 секунд.

В цепочке шаг с базой региона («🌍 По региону цепочки» или скрипт с шаблоном) выполняется для **одного** региона, выбранного перед запуском. Прогона цепочки по всем регионам сразу нет.
